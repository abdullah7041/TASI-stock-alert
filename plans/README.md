## Direction — options for the maintainer, not defects

Not planned; these are strategy calls, not problems to fix.

- **Finish the managed-runtime cutover.** `docs/managed-runtime-cutover.md`:
  "The code for the managed runtime is committed and tested offline. Nothing in
  GCP has been provisioned." `runtime/job.py`, `runtime/state.py`,
  `deploy/Dockerfile`, `deploy/cloud-scheduler.yaml`, `requirements-runtime.txt`
  all exist. GitHub's scheduler drift (35–59 min, dropped triggers) is the root
  cause the pending branch works around with a backstop cron. Trade-off: GCP
  cost and a second deploy target, for a system currently free to run.
- **Score the engine's own calls the way you score the model's.** `grade_leans`
  (`main.py:731`) grades the LLM lean daily against realised direction. The
  rules engine's own BUY/SELL/TRIM calls get no scorecard — the thing that
  decides is the thing not measured. History, reconcile mode, and realised
  prices are already in place. Trade-off: you may not like the answer.
- **Feed the entry forecast.** `research/entry_forecast.py` has a full
  `release_gate` (Brier skill, log-loss skill, ECE, expectancy, stability,
  sample size, bootstrap lower bound), it is tested, and `unavailable_forecast`
  genuinely returns `status: "available"` when metrics pass. But
  `research/forecast_metrics.json` is only ever read — nothing writes it and the
  file does not exist. The gate and the cockpit contract are built; the model
  that would feed them is not. Trade-off: real modelling work, and the gate is
  deliberately strict enough that it may correctly refuse what you build.

  Not worth the change.

  run, but the whole repo packs to 647 KiB after 323 commits — git handles this
  fine for years. Non-problem.

  uses the Cloudflare Images binding, not `sharp`, and `postcss` is build-time.
