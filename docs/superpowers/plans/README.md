## Executor hazard — agent worktrees start on a stale base (observed 2026-08-10)

Worktrees created for executor agents at this repo are **not** based on current
`main`. Three separate runs landed on `35cab31` or `8a4e901` — bot
`state update [skip ci]` commits, up to 20 behind. An executor that trusts its
worktree HEAD will read an outdated copy of its own plan file and measure a
baseline that no longer exists.

Every dispatch prompt should therefore begin with a step-zero block that:

1. proves isolation (`git rev-parse --show-toplevel` contains `worktrees`),
2. prints `git rev-parse --short HEAD` and `git status --porcelain`,
3. runs `git merge-base --is-ancestor HEAD <target>`, and
4. **explicitly authorises** `git reset --hard <target>` when that is a clean
   fast-forward on an empty working tree — otherwise stops.

Getting this wrong in either direction costs a run. A prompt that says only
"stop if you are not on the base" wastes the dispatch (observed once); saying
nothing lets the executor silently work from stale plan text (observed once).

## Executor hazard — worktree deregistration (observed 2026-08-10)

Worth knowing before dispatching any executor at this repo.

An executor for plan 06 backgrounded `npm install` and ended its turn to wait
for it. While it was parked, its worktree was **deregistered** — it vanished
from `git worktree list` and its `.git` file was removed — but the directory
survived, holding `node_modules` and an already-modified `package.json`.

The dangerous part: a directory under a repo with no `.git` of its own is not an
error to git. It walks up. So `git -C .claude/worktrees/agent-<id> rev-parse
--show-toplevel` returned the **main repo root**, and `git status` there reported
the **main repo's** status. Had that agent been resumed, its next `git add`,
`git checkout --`, or `git commit` would have operated on the user's real
working tree while it believed it was sandboxed.

The main tree was verified untouched (`package.json` still `16.2.6`, no modified
tracked files) and the agent was abandoned rather than resumed.

Two mitigations, now baked into dispatch prompts:

1. **Never background a long command and end the turn.** Run `npm ci` and
   `npm run build` in the foreground with an explicit long timeout.
2. **Prove isolation before any git write.** First command must be
   `git rev-parse --show-toplevel`; if it is not a path under `worktrees`, stop
   immediately and run no git write commands.

A stale orphaned directory may remain at
`.claude/worktrees/agent-a247a4185389f869c`. It is not a registered worktree.
Deleting it is safe but is the operator's call.

## Findings surfaced but not planned

Real, evidence-backed, below the bar for this batch. Listed so they are not
lost.

- **`GET /api/dashboard` has no app-level auth** (`app/api/dashboard/route.ts:3-9`)
  — it relies entirely on the hosting platform's private-site gate, unlike
  `/api/dashboard/ingest` which carries its own bearer token. Defense in depth.
  Check whether plan 01's `app/lib/dashboard-access.ts` changes this picture
  before filing anything.
- **Discord failure discards the run's state** — `mode_digest` returns 1 when
  `send_discord` fails (`main.py:353`), which fails the workflow step, which
  skips "Commit state", which loses `history.json` and breaks the next day's
  deltas. A Discord outage should not cost a day of history.
- **`news_archive.jsonl` is 302 KB, append-only, and committed on every digest
  run.** Roughly 64 lines a day. `news.archive_headlines` (`news.py:158-180`)
  documents why it exists — it is the only path to ever validating news against
  outcomes — so the growth is intentional, but the storage strategy is not
  sustainable in git indefinitely.
- **`news._fetch_rss` parses remote XML with `xml.etree.ElementTree`**
  (`news.py:70`). Entity-expansion exposure on a CI-only surface, from two feeds
  (Google News, Argaam). Low stakes, non-zero.
- **`disclosures.match_company` substring-matches short aliases**
  (`disclosures.py:75-76`) against an all-company feed. `config.py:23` lists
  `"EIC"` as an alias — a three-character plain substring against every Tadawul
  filing title. `config.py:36-38` already notes real coverage never uses the bare
  initialism, so the alias is both ineffective and false-positive prone.
